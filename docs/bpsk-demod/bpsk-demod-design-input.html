1. 試行の目的

MATLAB Agentic ToolkitとSimulink Agentic Toolkitを使い、単純なBPSK復調器の設計・検証・再利用可能な資産化を試す。まずMATLABでアルゴリズムを検討し、その後Simulinkで周辺機能と接続して確認する。

システム設計の結果として、固定プリアンブルを先頭に持つフレーム形式が要求されているものとする。受信信号は、このフレームを連続送信するBPSK信号とする。変調方式、公称ビットレート、フレーム形式は既知とし、データ部の内容は未知とする。

2. システムアーキテクチャ

ADCで実数のIF信号をサンプリングし、デジタルフロントエンドのDDCで複素ベースバンドIQへ変換する。今回の主な設計対象は、その後段のBPSK復調部とする。

機能役割・仮設定
ADC（前段）中心周波数200 kHzの実数IF信号を、1 MS/s・12 bitで標本化する。アナログ側の帯域制限は実施済みとする。
DDC（前段）200 kHzを中心にベースバンドへ周波数変換し、低域通過フィルタとレート変換で80 ksample/sの複素IQを出力する。レート比は2/25。設計試行では浮動小数点IQとして復調部へ渡す。
BPSK復調部DDC出力から残留する搬送波の周波数・位相ずれとシンボルタイミングを推定・補償し、各シンボルを0または1へ硬判定する。さらにプリアンブルを検出し、フレーム先頭の識別とビット極性の補正を行う。
後段プリアンブルを含む公称10 kbit/sの極性補正済みビット列とフレーム先頭信号を受け取り、データ部を取り出して記録・評価する。誤り訂正は行わない。

BPSKは1 symbolあたり1 bitのため、10 kbit/s＝10 ksymbol/s。復調部入力は公称8 sample/symbolとなる。ADC・DDCは初回試行では周辺モデルとして扱い、ハードウェア実装の最適化は対象外とする。

3. システムから要求されるフレーム形式

上位のシステム仕様として、次の固定長フレームを採用する。追加する制御用フィールドはプリアンブルのみとし、ヘッダ、長さ情報、CRCは設けない。

プリアンブル：32 bit0x1ACFFC1D（固定）
→
データ部：256 bit任意のデータ
項目仕様
送信順序プリアンブル → データ部。プリアンブルはMSBから送信する：
00011010 11001111 11111100 00011101
フレーム長288 bit固定。フレーム間の空白は設けず連続送信する。
ビットレートプリアンブル込みで10 kbit/s。1フレームは28.8 ms、データ部の実効レートは約8.89 kbit/s。
BPSKの割当てビット0を+1、ビット1を−1に対応付ける。

復調部は、プリアンブルの正規パターンと全ビット反転パターンを探索する。反転パターンを検出した場合は、そのフレーム全体のビット極性を反転して出力する。フレーム同期後は288 bit間隔のプリアンブル位置を確認する。検出閾値や同期の取得・解除条件はアルゴリズム設計時に決める。

プリアンブルはフレーム先頭と極性の識別に用いる。搬送波・タイミング同期が32 bit以内に完了することは要求せず、起動時は同期が成立するまでのフレームを出力対象外としてよい。

4. 復調部のインターフェース

方向信号仕様
入力受信IQDDCからの複素ベースバンド信号。80 ksample/s、浮動小数点。
入力リセット内部状態を初期化し、同期の取り直しを開始する。
出力硬判定ビット極性補正済みの0または1。プリアンブルを含むフレーム全体を、公称10 kbit/sで出力する。
出力ビット有効信号出力ビットを後段が取り込めるタイミングを示す。搬送波・タイミング・フレーム同期または極性が未確定の間は無効とする。
出力フレーム先頭信号有効な出力フレームの最初のプリアンブルbitと同時に通知する。

プリアンブルを含めて出力できるよう、検出・極性補正に必要な分のビットを保持してから出力する。プリアンブルの受信判定値を既知値で置き換えることはしない。

配列サイズ、処理チャンク長、同期方式、ループ係数などの詳細は、アルゴリズム設計時に決める。10 kbit/sは有効なビット列の公称レートを示し、ソフトウェアの呼出周期は規定しない。

5. 基本要求

ID要求
R-01システムで定めた32 bitプリアンブル＋256 bitデータの連続BPSKフレームを復調し、フレーム先頭を識別する。
R-0280 ksample/sの複素IQを入力し、プリアンブル込みで公称10 kbit/sの極性補正済み硬判定ビットを出力する。
R-03搬送波の初期位相とシンボルタイミングが未知でも同期する。DDC後の残留周波数ずれは±100 Hzを初期評価範囲とする。
R-04雑音のない条件で、同期後の10万bitに誤りがないことを確認する。初期位相がπ異なる場合も、プリアンブルによる極性補正後は送信ビットと一致すること。
R-05AWGN条件で、Eb/N0=6 dBにおける同期・極性補正後のデータ部のBERを5×10−3以下とすることを初期目標とする。評価にはデータ部100万bit以上を使用する。
R-06リセット後に再び同期・復調できる。MATLABとSimulinkで同じ入力条件を使い、復調結果の整合を確認できる。
システム仕様を利用した位相曖昧性の解消
BPSKの0/π位相曖昧性は、システムから要求されたプリアンブルを利用して解消する。出力で全体反転を許容せず、受信側の極性補正結果を評価する。評価器が送信真値を使ってビット反転を補正することは禁止する。フレーム途中の位相スリップは誤りとして記録し、CRCによる検出は保証しない。

6. 最初の検証と成果物

試験信号は、固定プリアンブルとランダムな256 bitデータ部で構成する。送信パルスはRRC、ロールオフは0.35を仮設定とし、復調側でも対応する整合フィルタを用いる。復調部には既知のプリアンブルとフレーム長を設定する。データ部の送信真値は評価器だけが参照し、復調部には与えない。

  1. 無雑音で動作確認：位相・タイミング・周波数ずれを与えて同期と硬判定を確認する。特に0/πの両極性で、フレーム先頭と補正後のビットが一致することを確認する。
  2. 雑音下で性能確認：AWGNを加えてBERを測定する。捕捉に要した時間、プリアンブルの誤検出・未検出、フレーム欠落、極性補正の誤りも記録し、受信成功フレームのBERだけで評価を完結させない。データ中にプリアンブルと同じ列が現れるケースも確認する。
  3. モデル化と再利用確認：MATLABとSimulinkの結果を比較し、ADC・DDCを含むハーネスから再実行できるようにする。

成果物は、MATLAB参照実装、Simulink復調モデル、ADC・DDCを含む試験ハーネス、共通パラメータ、試験結果、再実行手順とする。固定小数点化、コード生成、実機でのリアルタイム動作は次の段階で検討する。

本書は設計開始用の簡略仕様。同期判定の基準、捕捉時間の目標、細かな信号条件は初回設計で具体化する。性能シミュレーションは未実施。
