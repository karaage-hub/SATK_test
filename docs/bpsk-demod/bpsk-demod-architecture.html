1. 本仕様書の範囲と目的

検討状況・未決事項・検証記録

上位仕様 v0.3を満たすために必要な能力をF-01〜F-10として定義する。機能の目的、必要な情報、成立させる振る舞い、検証観点を整理し、第2章では方式に依存しない機能を定義し、第3〜5章では構成案Aのアーキテクチャ、動作仕様、インターフェースを定義する。第6章ではこれらをモデルとして表現する方法を規定する。

外部境界は、DDCからの80 ksample/s複素IQとresetを入力し、プリアンブルを含む極性補正済み10 kbit/sの硬判定列、bit_valid、frame_startを出力する範囲。ADC・DDC・送信源・チャネル・真値を使う評価器・後段のデータ抽出は対象外。

F番号は機能の識別子であり、実行順序ではない。各機能を別ブロックで実装することも要求しない。上位仕様に既にあるRRC整合処理、32 bitプリアンブル、288 bitフレーム、極性補正、受信データ保持は維持する。

3. 内部アーキテクチャ

2.1節の機能階層を具体的な処理へ割り当てた構成案Aを示す。方式に依存しない機能定義と、処理順序・方式・保持方針を持つ実現案を分けて記載する。

第2章は方式に依存しない機能定義。本章では、その機能を実現するための処理順序・方式・保持方針を仮置きする。機能CSVは引き続き機能の正本とし、本案の割当ては本章を正本とする。

3.1 全体の考え方

機能CSVを機能の正本、本章を構成案Aの割当ての正本とする。

搬送波周波数・搬送波位相・シンボル時刻の分担

位置 周波数ずれへの処理 搬送波位相への処理
A-03a：シンボル同期前 搬送波の周波数ずれを粗く推定・補償する。 位相同期の完了は要求しない。
A-04：タイミング同期 搬送波周波数の補償は担当しない。前段で低減した残留ずれの下で動作する。 搬送波位相の補償は担当しない。ここで合わせるのはシンボルの標本化時刻。
A-03b：シンボル同期後 粗補償の残留周波数ずれを微細に追従・補償する。 搬送波位相を判定軸へ合わせる。ただし0/πの2通りは区別できない。
A-06・A-07 → A-08：フレーム処理 周波数ずれは補償しない。 プリアンブルから0/πに対応するビット極性を識別し、A-08で反転を補正する。搬送波ループへ位相補正を戻す構成にはしない。

本案の順序：搬送波周波数の粗補償 → シンボル時刻の同期 → 残留搬送波周波数と搬送波位相の同期 → 硬判定 → プリアンブルによる0/π曖昧性の解消。シンボル同期前に搬送波位相まで合わせる構成ではない。

4. 動作仕様

本章は、構成案Aの各同期系の段階的な捕捉とフレーム同期追従を対象とする。

粗搬送波周波数、シンボルタイミング、残留周波数・位相、フレーム同期の段階的な捕捉を、1枚のUML状態遷移図で示す。状態内は継続動作、矢印は「イベント [条件] / 遷移時の処理」。条件のみの矢印は条件成立時の遷移を表す。

R1〜R3は処理ブロックの起動順序ではなく、捕捉の成立を確認する段階を示す。振幅正規化・粗周波数補償・RRC・タイミング同期・残留周波数／位相同期は受信データに対して継続動作する。タイミング同期は後段の位相同期完了を待たない。粗推定値は取得後に保持し、追従中はA-03bが残留ずれを補償する。

本図は構成案Aの捕捉段階を示す。再捕捉要求の発行条件、同期成立・解除の閾値、候補探索の詳細は未決定であり、単一の判定不成立だけでは再捕捉を要求しない。再捕捉要求が成立した後の保持・破棄範囲は4.2節に示す。出力の有効条件は第5章のインターフェース定義に従う。

4.2 再捕捉と外部reset

IF-17のresetとepochを使い、次の2つの操作を区別する。制御は対象の受信データより先に適用する。

操作受信処理・候補データ出力待ち・送出中のフレーム
再捕捉
reset=false、epoch更新		R1へ戻り、粗周波数推定から取得し直す。A-01〜A-08およびA-09aの受信履歴・同期判定・未確定候補を初期化し、位置番号を0から再開する。A-10は旧epochの未許可情報を破棄する。A-09bが既に同じキーの補正データ・記述子・許可を揃えて受理した完成フレームは、旧epochのキーを保持して送出を継続する。それ以外の旧epoch情報は破棄する。
外部reset
reset=true（最優先）		全処理と保持情報を初期化する。新しいreset区間の開始時にepochを更新し、保持中は更新しない。解除後にR1から再開する。許可済みを含めて破棄し、bits=0、bit_valid=false、frame_start=falseとする。

再捕捉要求1回につきepochを1回更新する。同じ追従不能状態を連続して新規要求として扱わず、再捕捉開始時に旧判定を無効化する。各ループの初期値、成立・解除閾値、保持容量は詳細設計で決める。

5. インターフェース

構成案Aの接続信号を、データと付随情報をまとめたレコードとして定義する。モデルへの表現方法は第6章に示す。

5.1 共通ルール

  • 型：IQ・シンボルはcomplex double、bitはuint8（0/1）、フラグはboolean、位置・epochはuint64とする。初回参照設計の型であり、実機型は別途検討する。
  • 有効性：validは新しいレコードの存在を示し、同期成立とは区別する。valid=falseのデータは処理せず、bit位置も進めない。有効なレコードは受信順に一度だけ処理する。
  • 位置：sample_indexは入力サンプル位置、symbol_indexは候補シンボル位置（ともに0始まり）。bit_indexはsymbol_indexを継承する。同期未成立の候補も数え、処理遅延による位置の書換えや単純な8分の1換算は行わない。
  • 対応付け：epochは初期化区間を識別する。フレームのデータ・極性・出力許可は、同じキー（epoch, start_bit）で照合する。start_bitはプリアンブル先頭のbit位置。
  • reset：データ処理より優先し、保持中は新規データを処理しない。epochは実行開始時0とし、外部reset区間の開始または再捕捉要求時に更新する。reset保持中は更新しない。再捕捉時の許可済みフレームの扱いは4.2節に従う。

5.4 フレーム出力の成立条件

同じフレームキーの情報を対応付け、以下の条件で出力する。

  • 受信完了：A-09aで288 bitを欠落・重複なく収集し、全bitの同期状態を集約する。
  • 極性補正：A-08で確定済みのFrameDescriptorに従って補正する。受信プリアンブルも同じ規則で補正し、既知値に置換しない。
  • 出力許可：A-10でcomplete AND sync_ok_all AND confirmed AND polarity_validを判定する。現在の同期状態で、対象フレームの受信結果を代用しない。
  • 送出：A-09bでCorrectedFrame・FrameDescriptor・FramePermissionを照合する。許可時はbit_validを立て、先頭bitでframe_startを立てる。不許可なら破棄する。許可済みフレームは後続の同期喪失では中断せず、外部resetで無効化する。

6. モデル化仕様

第2〜5章で定義した機能・アーキテクチャ・動作仕様・インターフェースを、以下のモデルとして作成する。導出したアーキテクチャ、詳細機能に基づく機能要件、モデル要素の対応を確認できるようにする。

使用ツール一覧 Simulink：詳細機能・アーキテクチャ・インターフェースの表現に使用する。MATLAB：CSVの読込み、データディクショナリの生成・整合確認に使用する。Stateflow：利用可能な場合に状態遷移の表現に使用する。System ComposerやRequirements Toolboxは必須としない。
詳細機能表現方法

Simulinkのモデル要素の説明に、第2章で導出したF-01〜F-10を機能要件として記載する。各機能の目的、入出力情報、成立させる振る舞い、状態・resetの扱いを示し、対応するF番号と上位要求R番号を付与する。要件管理専用ツールを用いない代替として、機能一覧・要求対応表のCSVを正本とし、F番号でモデル要素と対応付ける。

対応する設計データ：

  • bpsk-demod-functions.csv：機能一覧
  • bpsk-demod-traceability.csv：上位要求との対応
アーキテクチャ表現方法

Simulinkのサブシステム、入出力端子、接続線を用いて、第3章で導出した構成案Aを表現する。各処理単位（A番号）をサブシステムに割り当て、信号経路・制御情報と詳細機能（F番号）の対応を示す。System Composer等の専用アーキテクチャツールの代替として、初期モデルは入出力端子と接続を中心に構成する。

対応する設計データ：

  • bpsk_demod_architecture.slx：構成モデル
  • bpsk-demod-static-structure.json：モデル構造・機能との対応
インターフェース表現方法

SimulinkのInport／Outportとデータディクショナリ（SLDD）を用い、第5章のインターフェースを表現する。Simulink.Bus／BusElementでデータ構造、型、次元、実数／複素数と説明を定義し、各端子から参照する。MATLABでCSV正本から辞書を生成し、端子との整合を確認する。有効条件やreset時の扱いなど型で表せない契約は、端子・型の説明に記載する。

対応する設計データ：

  • bpsk-demod-interfaces.csv：接続一覧
  • bpsk-demod-interface-fields.csv：フィールド定義
  • bpsk-demod-interface-contracts.json：インターフェース契約
  • bpsk_demod_interfaces.sldd：データディクショナリ
動作仕様表現方法

Stateflowが利用可能であれば、第4章の捕捉状態・遷移条件・遷移時の処理をチャートで表現する。利用できない場合は、Simulinkの注釈・モデル要素の説明に状態と遷移条件を記載し、本仕様書の状態遷移図への参照を付ける。この代替表現は実行可能な状態機械を意味しない。未決定の閾値や条件は独自に確定しない。

対応する設計データ：

  • bpsk-demod-architecture.html：第4章の状態遷移図

6.1 データディクショナリへの表現

config/bpsk_demod_interfaces.slddにSimulink.Bus／BusElementを格納し、モデルの各端子から型を参照する。第5章で参照するフィールド一覧CSVのフィールド名、型、次元、実数／複素数、意味を辞書へ対応付ける。SLXとSLDDをセットで管理する。

フィールド一覧CSVを正本としてMATLABで辞書を生成し、CSV・辞書・端子設定の整合を確認できるようにする。意味上の単位（sample／bit等）はDescriptionに記載し、物理単位や実行周期と区別する。有効条件やフレーム対応付け等の動作契約は説明として保持し、型定義だけで動作検証されたものと扱わない。
